## 2. Dataset selection (FIXED — do not change)

### MS COCO (Common Objects in Context) via Hugging Face

- **Catalog:** Hugging Face Datasets (`https://huggingface.co/datasets`)
- **Dataset card URL:** `https://huggingface.co/datasets/HuggingFaceM4/COCO` (or the mirror `https://huggingface.co/datasets/nielsr/coco-100` for faster sampling)
- **Original source:** `https://cocodataset.org/`
- **Why this dataset:**
  - It is **multimedia**: images + text captions (image-text pairs), exactly what the assignment asks for.
  - It is one of the most studied datasets in computer vision, with extensive documentation, known limitations, and published bias analyses.
  - It has a **clear license** (CC-BY 4.0 for annotations; Flickr CC-BY / CC-BY-SA for images), making the legal analysis non-trivial and educational.
  - Creation method is **смешанный** (mixed): photos collected automatically from Flickr + captions annotated manually by crowd workers on Amazon Mechanical Turk — a textbook example of the "mixed" category.
  - It is accessible via the public Hugging Face API (no auth required for metadata and previews).
- **Known limitations** (from the COCO paper and subsequent literature):
  - Geographic/cultural bias: Flickr skews toward Western, English-speaking, affluent users.
  - Only 80 object categories — many common objects are missing.
  - Gender bias in annotations (well-documented in feminist AI research).
  - Aesthetic bias: photos are "Flickr-quality," not representative of real-world scenes.

### Step 7 — Write the "what NN can/cannot be trained" analysis

In `./logs/model_analysis.md`:

**Models that CAN be trained/fine-tuned on COCO:**
1. **Image captioning model** (e.g., BLIP, Show-Attend-Tell) — the 5 captions per image provide direct supervision for image-to-text generation.
2. **Object detection model** (e.g., YOLO, Faster R-CNN) — the bounding box annotations for 80 categories are the standard supervision for detection.
3. **Instance segmentation model** (e.g., Mask R-CNN) — the per-pixel masks enable segmentation training.
4. **Image-text matching / CLIP-like model** — the image-caption pairs enable contrastive learning for image-text alignment.
5. **Visual question answering (VQA) model** — combined with question annotations (COCO-VQA), the dataset supports VQA training.

**Models that CANNOT be trained on COCO (and why):**
1. **Text-only LLM (e.g., GPT-style)** — the captions are too short (average ~10 words) and too limited in vocabulary (only describing 80 categories). No coherent text corpus for language modeling. Need billions of words (lecture 2.3: ChatGPT trained on 300B words).
2. **Audio model (speech recognition, music generation)** — COCO has no audio data. Need a dedicated audio dataset (e.g., LibriSpeech, Common Voice).
3. **Video model (action recognition, video generation)** — COCO images are static, no temporal dimension. Need a video dataset (e.g., Kinetics, HowTo100M).
4. **Generative image model from scratch (e.g., Stable Diffusion)** — COCO images are real photographs with limited stylistic diversity. While COCO can be used for image-text pair training in a diffusion model, training a high-quality generative model from scratch requires a much larger and more diverse dataset (LAION-5B has 5B pairs vs COCO's 330K). COCO alone would produce a weak generative model.
5. **Code generation model** — no code in the dataset.

Course concept link: «специфика задачи» (lecture 2.5) — data must match the task. COCO is specific to visual understanding tasks, not text/audio/video/code.

### Step 8 — Write the legal analysis

In `./logs/legal_analysis.md`:

**License structure of MS COCO:**
1. **Annotations** (captions, bounding boxes, segmentation masks): **CC-BY 4.0** (Creative Commons Attribution 4.0). Source: `https://cocodataset.org/#termsofuse`
2. **Images**: the images themselves are hosted on Flickr and retain their original Flickr licenses. Most are **CC-BY** or **CC-BY-SA**. The COCO team filtered for CC-licensed images.
3. **Dataset metadata** (on Hugging Face): typically CC0 or follows the annotation license.

**What the license allows:**
- **Educational use:** YES — CC-BY explicitly permits educational use, including in university coursework, with attribution.
- **Commercial use:** YES — CC-BY permits commercial use, including building and selling products trained on the dataset, with attribution.
- **Modification:** YES — both CC-BY and CC-BY-SA allow creating derivatives.
- ** Redistribution:** YES — both licenses allow redistribution.

**Requirements:**
- **Attribution (BY):** must credit the dataset. Standard citation: «Microsoft COCO: Common Objects in Context. Lin et al., ECCV 2014.»
- **ShareAlike (SA, for CC-BY-SA images only):** if you redistribute modified versions of CC-BY-SA images, you must license the derivative under the same license. This applies to individual images, not to models trained on them.

**Conclusion:** MS COCO can be used in both educational and commercial projects, provided that:
1. The dataset is cited (Lin et al., 2014).
2. The CC-BY 4.0 license for annotations is respected.
3. Individual image licenses (mostly CC-BY / CC-BY-SA) are respected if redistributing the images themselves.
4. Models trained on the dataset do not inherit the image licenses (model weights are not derivative works of the images under most interpretations, but this is a legal gray area — for commercial products, consult a lawyer).

Russian legal note: under Russian Civil Code Part 4 (ГК РФ Часть 4), Creative Commons licenses are recognized as valid licensing terms. Using CC-BY data in Russia is legal with attribution.
