# Методика получения данных

Все результаты задания получены реальными запросами к API Polza.ai. Ни один
ответ ассистента, ни один аудиофайл и ни одна метрика не написаны вручную:
тексты лежат в `logs/conversation.json`, параметры синтеза — в
`logs/tts_results.json`, распознавание — в `logs/stt_check.json`, измерения
речи — в `logs/prosody.json`. Скриншоты собраны из этих же файлов.

## Доступ и модели

| Параметр | Значение |
| --- | --- |
| Провайдер | Polza.ai, OpenAI-совместимый API |
| Base URL | `https://polza.ai/api/v1` |
| Авторизация | `Authorization: Bearer $POLZA_API_KEY` |
| LLM | `google/gemini-2.5-flash` |
| TTS | `google/gemini-3.8-flash-lite-tts`, голос `Kore` |
| STT (самопроверка) | `openai/whisper-large-v3` |

Переменная окружения `POLZA_API_KEY` в системе не была задана, поэтому ключ
читался из локального файла `.polza_key` (в поставку не входит и удалён после
сборки). Замены моделей не потребовались: обе модели из задания есть в
каталоге Polza.ai и доступны на тарифе по умолчанию.

## Беседа

`scripts/run_conversation.py` отправляет 12 реплик пользователя
последовательно, сохраняя весь массив сообщений: каждый следующий запрос
содержит системный промпт и все предыдущие пары «пользователь — ассистент».
Параметры: `temperature = 0.7`, `max_tokens = 900`. Ответы записаны как есть,
включая разметку Markdown и обрезанное слово «планиру» в первой реплике.

Системный промпт (полный текст — в `logs/conversation.json`):

> Ты — голосовой ассистент для планирования путешествий. Отвечай на русском
> языке, дружелюбно и по делу. Если пользователь меняет тему — отвечай на новый
> вопрос, но помни всё, что обсуждалось ранее, и можешь вернуться к нему.
> Адаптируй стиль под пользователя: если он говорит коротко — отвечай кратко;
> если развёрнуто — отвечай подробно. В ответах с числами, ценами и датами пиши
> их прописью для удобства озвучки.

Требование писать числа прописью добавлено заранее: это снимает нагрузку с
нормализатора TTS и позволяет проверить, как модель читает числительные.

## Синтез речи

`scripts/run_tts.py` озвучивает ответы реплик 1, 3, 6, 7, 9 и 11 — шесть
файлов, покрывающих начало беседы, смену темы и возврат к ней. Перед отправкой
текст очищается: удаляются `**`, `*`, заголовки, нумерация списков и
маркированные пункты, схлопываются пустые строки. В одном месте исправлена
опечатка модели: «планиру провести» → «планируете провести»; исходный текст
сохранён в протоколе, исправленный — в поле `speech_text`.

Провайдер игнорирует параметр `response_format` и возвращает JSON с полем
`audio` (base64) и `contentType: audio/wav`: WAV 24 кГц, моно, 16 бит.
Скрипт декодирует base64, проверяет длительность по заголовку WAV и
перекодирует в MP3 64 кбит/с моно через `lameenc` (ffmpeg в системе нет).
Поэтому в поставке лежат MP3, а метрики длительности взяты из декодированного
WAV.

## Проверка произношения

`scripts/verify_stt.py` отправляет каждый MP3 в `/audio/transcriptions`
(`openai/whisper-large-v3`, язык `ru`) и сравнивает распознанный текст с
исходным по нормализованному расстоянию Левенштейна. Это не часть задания, а
способ объективно найти ошибки произношения: на слух «Сююмбике» и «Сюембике»
различить трудно, а распознавание слышит второй вариант в двух файлах из трёх,
где встречается слово (реплики 6 и 9).

## Измерение просодии

`scripts/analyze_audio.py`:

- декодирование MP3 через `miniaudio` (файл читается байтами, потому что
  библиотека не открывает пути с кириллицей);
- паузы — по огибающей RMS с окном 20 мс, порог 200 мс: интервалы тишины
  короче 200 мс не считаются паузами;
- основной тон — `librosa.pyin`, 75–320 Гц, кадр 1024, шаг 240 (10 мс).
  Алгоритм Praat `to_pitch_cc` давал октавные ошибки (скачки 164 → 245 Гц на
  ровных гласных), поэтому для тона выбран pYIN, а HNR остался за Praat;
- HNR — `to_harmonicity_cc` по озвученным кадрам;
- темп — по числу слов в исходном тексте и длительности речи без пауз.

## Снимки интерфейса и визуализации данных

Три снимка интерфейса сделаны в браузере 26.11.2026. Экран беседы —
`01_chat_screen_live.png`: живой веб-интерфейс `https://polza.ai/dashboard/playground`,
в котором те же 12 реплик таблицы 1 были повторно отправлены на
`google/gemini-2.5-flash` (с 01:05 до 01:08 MSK, 4,3007 ₽); из кадра вырезаны
боковая панель с именем аккаунта и балансом. Основная сессия работы шла через
API Polza.ai и в истории браузера не отображается, поэтому снимок — это
отдельный повтор той же беседы, а не запись основной сессии. Карточки моделей
`google/gemini-2.5-flash` и `google/gemini-3.8-flash-lite-tts` сняты
`scripts/crop_model_screens.py` из копий страниц каталога (ширина окна 1440 px,
масштаб 1,5).

`scripts/build_screens.py` собирает ещё две HTML-страницы из JSON-протоколов и
рендерит их тем же Chrome (1400 px по ширине, обрезка по маркеру): протокол
беседы (реплики 1, 7, 9 и полный список из 12 реплик) и анализ речи
(осциллограмма с паузами, контур тона, таблица метрик). Это визуализации
данных, а не снимки интерфейса; все числа на них совпадают с JSON-файлами.

## Воспроизведение

```
python scripts/check_models.py       # проверка каталога
python scripts/run_conversation.py   # 12 запросов к LLM
python scripts/run_tts.py            # 6 запросов к TTS + MP3
python scripts/verify_stt.py         # 6 запросов к STT
python scripts/recalc_costs.py       # пересчёт стоимости LLM
python scripts/analyze_audio.py      # паузы, тон, HNR
python scripts/capture_polza_ui.py   # снимок экрана беседы (снимок живой страницы)
python scripts/crop_model_screens.py # карточки моделей
python scripts/build_screens.py      # две визуализации данных
python scripts/derive_stats.py       # computed_stats.json
python scripts/check_consistency.py  # сверка чисел и дат
python scripts/build_report.py       # DOCX
python scripts/make_pdf.py           # PDF
```

Повторный запуск `run_conversation.py` и `run_tts.py` снова спишет деньги:
скрипты не кэшируют ответы API, а пишут новые протоколы.
