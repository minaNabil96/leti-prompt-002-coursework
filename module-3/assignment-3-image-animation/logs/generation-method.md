# Метод генерации

## Сервис и доступ

Все генерации выполнены через API платформы **Polza.ai** (`https://polza.ai/api/v1`).
Сайт и API доступны из России: запросы к `https://polza.ai/api/v1/models` и `/v1/balance`
вернули 200, архивные копии не понадобились. Ключ доступа хранился вне проекта
(`ref-analysis/.polza_key`) и в отчёт не переносился.

## Изображения (S1, S2)

- Модель: `tongyi-mai/z-image`, режим text-to-image.
- Запрос: `POST /api/v1/media` с телом `{"model": "tongyi-mai/z-image",
  "input": {"prompt": "...", "aspect_ratio": "1:1" | "16:9"}}`.
- Ожидание: `GET /api/v1/media/{id}` до `status = completed`; результат — `data.url`
  или `data.b64_json`.
- Стоимость: 1,40 ₽ за изображение (по `usage.cost_rub`).

## Анимации (A1–A3)

- Модель: `bytedance/seedance-2-mini`, режим image-to-video.
- Запрос: `POST /api/v1/media`:

  ```json
  {
    "model": "bytedance/seedance-2-mini",
    "input": {
      "prompt": "<промпт движения>",
      "images": [{"type": "base64", "data": "<base64 PNG/JPG>"}],
      "duration": "5",
      "resolution": "480p",
      "aspect_ratio": "auto",
      "generate_audio": false
    }
  }
  ```

- Ожидание: `GET /api/v1/media/{id}` до `status = completed`; результат — `data.url`
  (MP4 в хранилище Polza.ai). Эндпоинт `GET /api/v1/media/{id}/operations` в OpenAPI
  описан, но в этой работе состояние читалось через `/media/{id}`, который возвращает
  и `status`, и `data`.
- Страница модели подтверждает параметры: `images` 0–9, `duration` 4–15 с,
  `resolution` 480p/720p, `generate_audio` true/false, `aspect_ratio` от 16:9 до 21:9
  и `auto`. Значения по умолчанию на сайте — 15 с, 720p, звук включён; в работе
  использованы 5 с, 480p и звук выключен, чтобы уложиться в бюджет и получить
  беззвучный ролик.
- Стоимость: 12,825 ₽ за 5-секундный ролик в 480p, то есть 2,565 ₽/с — нижняя
  граница указанного на странице диапазона 2,56–6,75 ₽/с.
- Интенсивность задаётся только текстом промпта: модель одна и та же для трёх роликов.

## Замены и сбои

- Замены модели не было: `seedance-2-mini` принял все три изображения.
- При первом ролике клиентский скрипт упал уже после завершения задачи — при разборе
  ответа, где `data` пришёл объектом, а не списком. Задача к этому моменту была
  выполнена и оплачена один раз; файл скачан повторно по `id` из
  `GET /api/v1/history/generations` и `GET /api/v1/media/{id}`. Повторной генерации
  и повторного списания не было.
- Ошибок модерации, таймаутов и отказов API не зафиксировано.
